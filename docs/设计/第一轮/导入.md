# 功能一：跨平台账单导入

> 代码位置：`backend/importer/`
> 当前状态：微信 ✅ 实测通过 / 支付宝 ⚠️ 未验证 / 第三方平台 ⬜ 未开始

---

## 一、设计目的

**用户的账单散落在各个平台，谁也看不见全貌。**

微信一份 xlsx、支付宝一份加密 zip、银行一份 PDF、美团一份 CSV——要把它们合并成一张能查询的表，中间有四道坎：

1. **格式不同**（xlsx / csv / zip / 编码）
2. **列名不同**（"交易类型" vs "交易分类"）
3. **词表不同**（收/支写成 `支出` / `收入` / `/`）
4. **表头位置不固定**（微信第 18 行才是表头，前面 17 行是账号信息）

这四道坎就是导入器要解决的全部问题。

---

## 二、多平台架构：配置驱动优先

### 已经踩过的坑

第一版设计是 `wechat.py` + `alipay.py` 两个硬编码解析器。实测微信后立刻发现问题——**每加一个平台就要复制一遍「打开文件、找表头、认列名、归一化」**，美团一个、银行五个，加到第十个平台时代码就没法维护了。

### 所以改为：适配器 + 配置

```
backend/importer/
├── __init__.py      编排：识别平台 → 解析 → 全事务入库
├── base.py          归一化工具 + Row 数据类 + dedupe_key
├── wechat.py        需要代码：xlsx + 表头搜索
├── alipay.py        需要代码：加密 zip + 编码探测 + 表头搜索
├── generic_csv.py   通用：绝大多数第三方平台走这里
└── mappings/
    ├── meituan.yaml
    └── cmb.yaml
```

### 什么时候写代码，什么时候写 YAML

| 情况 | 处理方式 |
|---|---|
| 列名不一样 | **YAML**，12 行配置，不用写代码 |
| 方向/状态的词表映射 | **YAML** |
| 文件读不出来（加密 zip、xlsx） | 代码 |
| 表头不在第一行 | 代码 |
| 数据分散在多处（银行 PDF 多账户） | 代码 |

**加一个美团 = 放一个 `meituan.yaml` + 导入器自动注册平台，数据库零结构改动。**

`mappings/meituan.yaml` 长这样：

```yaml
name: 美团
filenames: ["美团*.csv", "*美团*"]
columns:
  交易时间: tx_time
  订单号:   tx_no
  商家名称: counterparty
  订单金额: amount
  收/支:    direction
  支付方式: pay_method
  交易状态: status
direction_map:
  支出: 支出
  收入: 收入
status_drop: [已取消, 已关闭]
```

## 三、归一化规则（实测得出）

### 真实文件里的脏值，实测统计

| 现象 | 数量 | 处理 |
|---|---|---|
| 微信中性交易 `收/支 = '/'` | 48 笔 | → `direction='中性'` |
| 微信 `备注 = '/'` | 大量 | → `''` |
| 微信 `支付方式 = '/'` | 168 笔 | → `''`（且这些全是中性交易） |
| 微信 `商户单号 = None` | 部分 | → `''` |

### `base.py` 的归一化函数

| 函数 | 作用 |
|---|---|
| `clean()` | `/` `\` `-` `null` `None` 空串 → `''` |
| `norm_direction()` | `支出/收入` 原样；`/` `不计收支` `其他` → `中性` |
| `norm_amount()` | 去 `¥` 和千分位逗号 → `float`，两位小数 |
| `norm_time()` | 统一到 `YYYY-MM-DD HH:MM:SS` |
| `should_drop()` | 状态含「交易关闭/已关闭/支付失败/还款失败/已取消」→ 丢弃 |

> ⚠️ **`'/'` 这个坑不实测发现不了。** 文档上写的是"空"，实际文件里是斜杠。

### 派生字段

```
date    = tx_time[:10]
month   = tx_time[:7]
year    = tx_time[:4]
weekday = datetime.weekday()   # 0=周一
hour    = int(tx_time[11:13])
```

全部在导入时算好存进去，查询时不用再解析字符串。

## 四、去重

```python
if tx_no:
    dedupe_key = f"{source}|{tx_no}"          # 优先，99% 的情况
else:
    dedupe_key = f"{source}|md5:{hash(...)}" # 兜底指纹
```

**兜底方案有代价**：同一时刻、同一金额、同一对手方的两笔真实交易会被误判成重复。

**所以 `skipped`（重复笔数）必须返回给用户看，不能静默吞掉。** 这是设计里唯一一处「宁可暴露问题也不假装没事」。

实测：二次导入同一文件 → `inserted=0, skipped=1075` ✅

## 五、事务：全进或全不进

```python
with db.transaction(conn) as c:
    ensure_platform(c, pid)
    for i, r in enumerate(rows, 1):
        c.execute(INSERT_SQL, r.to_sql_tuple(batch_id))  # 任何一行失败 → 整体 ROLLBACK
```

**实测验证**：第一次导入时撞上外键失败（`platforms` 表是空的），结果 **一条都没写进去**，错误信息精确到「第 1 行」。

如果没事务，这里会留下 1~846 笔的残缺数据，界面数字看着正常，但下次重导会被 `dedupe_key` 跳过——**永久缺失，且无人察觉**。

## 六、平台自动注册（实测发现的设计缺陷）

第一次跑就崩了：

```
ValueError: 第 1 行写入失败：FOREIGN KEY constraint failed
```

`transactions_raw.platform_id` 有外键指向 `platforms`，但没人往 `platforms` 插数据。

**修法不是加一个 `seed.sql` 手写平台，而是让导入器自动注册**：

```python
def ensure_platform(conn, platform_id):
    """导入时自动注册平台。
    不单独做 seed.sql —— 加一个新平台不应该需要改两处地方。"""
```

> 外键约束在建表时不报错，**只��第一次导入真实数据时才炸**。所以「能建表」不等于「能用」。

## 七、接口

### `POST /api/import/preview`

上传文件，解析但**不入库**，返回给用户确认。

```json
{
  "batch_id": "a3f9c2e1b7d4",
  "platform_id": "wechat",
  "platform_name": "微信支付",
  "confidence": 0.98,
  "total": 1075,
  "by_status": {"支付成功": 810, "已全额退款": 41, "已存入零钱": 128},
  "by_direction": {"支出": 835, "收入": 192, "中性": 48},
  "date_from": "2025-09-27",
  "date_to": "2026-09-25",
  "amount_sum": 31672.19,
  "sample": [{...}],
  "warnings": []
}
```

`confidence < 0.6` 时前端应弹窗让用户手动确认平台。

### `POST /api/import/commit`

```json
{
  "batch_id": "a3f9c2e1b7d4",
  "inserted": 1075,
  "skipped": 0,
  "failed": 0,
  "first_error": null
}
```

⚠️ `first_error` 有值时 `inserted` 一定是 0（事务回滚了）。

### `GET /api/import/history`

返回 `import_batches` 表内容。

## 九、已知风险

| 风险 | 后果 | 缓解 |
|---|---|---|
| 兜底 dedupe_key 误判 | 真实交易被当成重复丢弃 | `skipped` 暴露给用户 |
| 支付宝 ZIP 密码遗失 | 无法导入 | 用户重新导出 |
| 表头行号变化 | 解析失败 | 已改为**搜索**而非硬编码 |
| 平台新增未注册 | 外键失败 | `ensure_platform` 自动注册 |
| 金额单位不一致（有的平台导分） | 数字差 100 倍 | 各 adapter 负责归一化，测试要覆盖 |
