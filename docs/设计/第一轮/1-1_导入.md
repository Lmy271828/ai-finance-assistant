# 1-1 · 功能一：跨平台账单导入

## 目标

用户的账单散落在各个平台，谁也看不见全貌。我们要做到：

**把各类账单文件直接导入，统一成一张表，之后就能跨平台查询。**

最终要支持：

| 类型 | 举例 | 状态 |
|---|---|---|
| 钱包 | 微信支付、支付宝 | 🟡 微信已完成 / 支付宝占位 |
| 生活服务 APP | 美团、饿了么、大众点评 | ⬜ 未开始 |
| 银行卡 | 招商银行、建设银行… | ⬜ 未开始 |
| 电商 | 淘宝、京东 | ⬜ 未开始 |
| 其他 | 共享单车、话费充值… | ⬜ 未开始 |

---

## 当前状态

**只支持微信支付（`.xlsx`）。支付宝代码已写但未验证，其余一律未开始。**

第一轮不承诺多平台。**先把微信这一条链路做扎实**，多平台是后面的事。

支付宝保留一个占位实现，因为它的文件结构和微信差别很大（ZIP 加密、GBK 编码、列名变体多），将来大概率要单独写适配器。**现在不投入。**

---

## 已实测的部分

微信解析器用 1058 笔真实账单跑通：

```
✅ 与账单文件自带的汇总数字分毫不差（支出/收入/中性三档）
✅ 重复导入自动跳过（0 写入 / 1058 跳过）
✅ 解析中途失败 → 整体回滚，不留半截数据
✅ 脏值归一化（微信用 '/' 表示空，不是真正的空字符串）
```

实测过程中发现的、以后接别的平台一定会再遇到的问题：

- **表头不在第一行** —— 微信文件前 17 行是账号信息和汇总，第 18 行才是表头。已改成搜索表头，不硬编码行号。
- **词表不统一** —— 中性交易微信写 `'/'`，支付宝写「不计收支」。接新平台时都要各自映射。
- **兜底去重会误判** —— 没有交易单号时用「时间+金额+对方」算指纹，同一时刻同额的第二笔会被当成重复。所以重复笔数要展示给用户，不能静默吞。

## 验收标准

- [x] 微信 `.xlsx` 能导入
- [x] 解析结果与账单文件自带的汇总一致
- [x] 重复导入不产生新数据
- [x] 解析失败整体回滚
- [ ] 支付宝能导入（待密码验证）
