# 1-1 · 功能一：跨平台账单导入

## 目标

用户的账单散落在各个平台，谁也看不见全貌。我们要做到：

**把各类账单文件直接导入，统一成一张表，之后就能跨平台查询。**

最终要支持：

| 类型 | 举例 | 状态 |
|---|---|---|
| 钱包 | 微信支付、支付宝 | 🟡 微信已完成 / 支付宝占位 |
| 生活服务 APP | 美团、饿了么、大众点评 | ⬜ 未开始 |
| 银行卡 | 招商银行、建设银行… | ⬜ 未开始 |
| 电商 | 淘宝、京东 | ⬜ 未开始 |
| 其他 | 共享单车、话费充值… | ⬜ 未开始 |

**多平台是这一轮的目标，不是后面的事。** 微信只是第一个跑通的，不是唯一的。

本轮进度：

支付宝实测结果：2931 笔全部解析，**笔数与账单自报汇总完全一致**
（支出 1873 / 收入 163 / 中性 895），收入金额分毫不差。丢弃的 25 笔是
`交易关闭`+`还款失败`，本就不该入库。

⚠️ 导入时另有 1102 笔被跳过：全是「滴滴青桔骑行卡抵扣」且金额 **0.00**，
撞上 schema 的 `CHECK (amount > 0)`。对所有汇总贡献为 0，金额不受影响，
但 `skipped` 计数会偏大。

微信跑通过程中已经看清了多平台的真实难点（下面那三条），这些是后面接平台时要反复处理的，不是微信独有的。支付宝因为 ZIP 加密、GBK 编码、列名变体多，单独写了解析器——用户密码解压、GB18030 编码探测均已验证可用。

> ⚠️ **支付宝导出的 zip 是加密的，解压密码由用户自行提供，不要写进任何仓库或文档。**

**前端仍然是零进度**：上传页只是版式骨架，没调 `/api/import/preview` 和 `/commit`，支付宝的密码输入框也还没做。

## 已实测的部分

微信解析器用 1058 笔真实账单跑通：

```
✅ 与账单文件自带的汇总数字分毫不差（支出/收入/中性三档）
✅ 重复导入自动跳过（0 写入 / 1058 跳过）
✅ 解析中途失败 → 整体回滚，不留半截数据
✅ 脏值归一化（微信用 '/' 表示空，不是真正的空字符串）
```

实测过程中发现的、以后接别的平台一定会再遇到的问题：

- **表头不在第一行** —— 微信文件前 17 行是账号信息和汇总，第 18 行才是表头。已改成搜索表头，不硬编码行号。
- **词表不统一** —— 中性交易微信写 `'/'`，支付宝写「不计收支」。接新平台时都要各自映射。
- **兜底去重会误判** —— 没有交易单号时用「时间+金额+对方」算指纹，同一时刻同额的第二笔会被当成重复。所以重复笔数要展示给用户，不能静默吞。
