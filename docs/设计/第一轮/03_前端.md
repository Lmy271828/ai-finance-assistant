# 03 · 前端

> 骨架已搭好，队友负责填组件内容。
> 本文只说：**哪些文件不能动、哪些是他的活、以及为什么这么分。**

---

## 一、已有的是什么

后端 12 个接口已经能跑，前端要从零开始。

最直接的做法：让一个人把整个前端写完，另一个人先看着。

## 存在什么问题没解决

### 问题 1：两个人各写一套请求方式，最后对不上

```
队友 A:  api.get('/api/report/summary', { type, period, value })
队友 B:  api.get('/api/report/summary?type=x&period=y&value=z')
队友 C:  fetch('http://localhost:8000/api/report/summary', ...)
```

三种写法。后端 URL 改一个参数名，三处一起崩。

更糟的是 C——他不知道 `baseURL`，最后在 `vite.config.ts` 里配 proxy 绕过去。**开发能跑，部署直接挂。**

### 问题 2：前端不知道后端返回什么形状

`{"total": ..., "count": ...}` 里哪个字段可能不存在？前端只能试。试错了不报错，只显示空白。

### 问题 3：三个人挑出三个红

支出的颜色，A 挑 `#e5484d`，B 挑 `#ef4444`，C 挑 `#dc2626`。第一轮结束界面就是花的。

### 问题 4：两个人按「层」分工，到联调才知道契约错了

我做完后端，他做完前端，第 5 天第一次对接。**这 5 天里两个人都建立在猜测上。**

## 二、提出的设计

### 设计 1：`vite.config.ts` 的 proxy —— 唯一不能省的 5 行

```typescript
server: {
  proxy: { '/api': { target: 'http://localhost:8000', changeOrigin: true } }
}
```

有了它，前端代码里一律写相对路径 `/api/xxx`。

**不写会怎样**：队友 100% 会硬编码 `http://localhost:8000`。开发时能跑，**部署时全线崩**。这是本项目返工代价最高的一处配置。

### 设计 2：骨架页带 `data-component` 标记

```html
<section class="card" data-component="summary"  data-api="/api/report/summary">
<section class="card" data-component="calendar" data-api="/api/report/calendar">
<section class="card" data-component="trend"    data-api="/api/report/trend">
<section class="card" data-component="category" data-api="/api/report/by-category">
<section class="card" data-component="method"   data-api="/api/report/by-method">
<section class="card" data-component="rank"     data-api="/api/report/income-rank">
```

**这个标记的价值不是代码，是省沟通。**

队友打开文件就知道「小结放这儿、日历放这儿」，而且知道每个区块对应哪个接口。**不用问。**

### 设计 3：`variables.css` 定变量不定样式

```css
--color-expense: #e5484d;
--color-income:  #30a46c;
--space-1: 4px; --space-2: 8px; --space-3: 16px; --space-4: 24px;
--chart-1..6: ...;
```

**你定色板和间距刻度，队友定布局。**

### 设计 4：`router/index.ts` 的 URL 参数名是契约

```
/bill?type=expense&period=month&value=2026-09&tab=summary
      ↑ 必须与 GET /api/report/summary?type=&period=&value= 一一对应
```

不定的话，队友想叫 `kind` 还是 `type`，后端就得跟着改，改了另一边全崩。

### 设计 5：骨架阶段接通一个真接口

`BillView.vue` 里 `MOCK_SUMMARY` 旁边留了接真实接口的示例。这样队友第一天就能照着模式接剩下 6 个。

## 三、不写 `api/` 层的理由

**它是包装函数，不是契约。**

11 个 `api/*.ts` 函数全是 `fetch(url) → json`，写它的人没获得任何思考，只是搬运。为它花半天不值得。

**契约由 `schemas.py` 和 Swagger 承担。** 队友启动后端后开 `/docs`，所有接口、字段说明、可试的真实返回都在那里。

代价是每个人会写得不一样——但那是风格问题，不是正确性问题。

## 四、分工

| 文件 | 谁能改 | 为什么 |
|---|---|---|
| `vite.config.ts` | **只有你** | proxy 唯一出处，改了全队崩 |
| `router/index.ts` | **只有你** | URL 参数是前后端共同约定 |
| `styles/variables.css` | **只有你** | 视觉一致性 |
| `views/*.vue` 骨架 | 你给结构，对方填内容 | 结构定好省沟通 |
| `api/*.ts` | 队友（如果要写） | 纯包装 |
| `components/*.vue` | **队友** | 9 个纯 UI 零件，无歧义 |

**队友要写的组件：**

```
TimeSelector  TypeToggle      顶部切换
DayCalendar   TrendBar        日历 / 柱状图
CategoryPie   CategoryList    环形图 / 二级列表
MethodList    IncomeRank      方式 / 排行
```

## 五、按功能切，不按层切

> ⚠️ **不要「我做后端他做前端」。** 那样两个人要到联调日才知道契约对不对，返工是全量的。

按功能切，每人 2-3 条端到端的竖线：

| # | 功能 | 后端 | 前端 | 怎么验证 |
|---|---|---|---|---|
| ① | 导入 | `importer/`（✅ 已完成） | ImportView | 传真账单，看 `skipped` 计数 |
| ② | 小结 + 日历 | ✅ 已完成 | TimeSelector DayCalendar | 页面上数字对不对 |
| ③ | 趋势 + 排行 | ✅ 已完成 | TrendBar IncomeRank | 同上 |
| ④ | 分类 + 方式 | ✅ 已完成 | CategoryPie CategoryList MethodList | 同上 |
| ⑤ | 修正闭环 | ✅ 已完成 | TxEditView | 改一笔，报告变，原始层没变 |
| ⑥ | MCP | ⬜ 待写 | — | AI 客户端能列出工具 |

**后端已经全部就绪，所以现在每一行都是「填前端」或「写 MCP」，没有需要重新谈契约的。**

## 六、坑位提醒（写进注释，队友别删）

骨架里故意埋了几个看起来奇怪的地方：

```js
// ⚠️ 9/3、9/4 无消费 → 后端不会返回它们，前端自己补零
```

```html
<p class="lock">🔒 这些字段由导入器写入，系统不提供任何修改入口</p>
```

```html
<span v-if="r.counterparty">{{ r.counterparty }}</span>   <!-- 空字符串不显示空白 -->
```

**这些不是笔误，是和后端的约定。** 队友改成「每天都有」「不判空」，联调时就会发现日历少格子。
