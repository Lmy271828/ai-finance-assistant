# 原始账单格式

> 文档目的：说清楚从微信/支付宝导出的原始文件里有哪些字段，我们只读不写、只写一次。
> 所有字段均为只读——导入时写入，之后不修改。

---

## 一、微信支付账单

### 导出方式
微信 → 我 → 服务 → 钱包 → 账单 → 常见问题 → 下载账单 → 选择时间范围 → 获取账单

导出一个 `.xlsx` 文件。

### 原始字段清单

| 微信列名 | 含义 | 我们的存法 |
|---|---|---|
| 交易时间 | 精确到秒 | ✅ 存 → `tx_time` |
| 交易类型 | 如"餐饮"、"转账红包"等 | ✅ 存 → `tx_type` |
| 交易对方 | 对方商户名或微信号 | ✅ 存 → `counterparty` |
| 商品 | 商品说明文字 | ✅ 存 → `item` |
| 收/支 | "收入"/"支出"/空 | ✅ 存 → `direction`（归一化为"支出"/"收入"/"中性"） |
| 金额(元) | 数值，带¥符号 | ✅ 存 → `amount`（恒为正） |
| 支付方式 | 如"微信支付-零钱"、"亲情卡"等 | ✅ 存 → `pay_method` |
| 当前状态 | "交易成功"、"已退款"等 | ✅ 存 → `status` |
| 交易单号 | 微信内部交易编号 | ✅ 存 → `tx_no`（去重优先 key） |
| 商户单号 | 商户侧单号 | ✅ 存 → `merchant_no`（去重兜底 key） |
| 备注 | 用户在微信里写的备注 | ✅ 存 → `remark` |

### 特殊处理

**去重 key**：
- 优先：`source` + `tx_no`
- 兜底：`source` + `tx_no` 为空时，用 `source` + 时间戳 + `amount` + `counterparty` 的 MD5

**状态过滤**：若 `status` 包含"交易关闭"、"已关闭"、"支付失败"，该行丢弃，不入库。

---

## 二、支付宝账单

### 导出方式
支付宝 → 我的 → 账单 → 右上角"..." → 导出 → 选择时间范围 → 确认 → ZIP 压缩的 CSV

### 原始字段清单

| 支付宝列名（常见变体） | 含义 | 我们的存法 |
|---|---|---|
| 交易时间 / 交易创建时间 / 付款时间 | 时间戳 | ✅ 存 → `tx_time`（优先"交易时间"） |
| 交易分类 / 类型 | 交易分类 | ✅ 存 → `tx_type` |
| 交易对方 | 对方 | ✅ 存 → `counterparty` |
| 商品说明 / 商品名称 / 商品 | 商品描述 | ✅ 存 → `item` |
| 收/支 | "收入"/"支出"/"不计收支" | ✅ 存 → `direction` |
| 金额 / 金额（元） / 金额(元) | 数值 | ✅ 存 → `amount` |
| 收/付款方式 / 收付款方式 / 付款方式 | 支付工具 | ✅ 存 → `pay_method` |
| 交易状态 / 当前状态 | "交易成功"/"退款"等 | ✅ 存 → `status` |
| 交易订单号 / 交易号 | 交易编号 | ✅ 存 → `tx_no` |
| 商家订单号 / 商户订单号 | 商户侧单号 | ✅ 存 → `merchant_no` |
| 备注 | 用户备注 | ✅ 存 → `remark` |

### 特殊处理

**编码**：可能为 GBK / GB18030 / UTF-8，读取时逐个尝试。

**退款识别**：`status` 或 `tx_type` 含"退款" → `is_refund = 1`。

## 三、最少原始字段清单（11 个）

所有平台归一化后，统一写入以下 11 个字段。**只写一次，不修改。**

| # | 字段名 | 类型 | 说明 |
|---|---|---|---|
| 1 | `source` | TEXT NOT NULL | "微信支付" / "支付宝" |
| 2 | `tx_time` | TEXT NOT NULL | "YYYY-MM-DD HH:MM:SS"，精确到秒 |
| 3 | `direction` | TEXT NOT NULL | "支出" / "收入" / "中性" |
| 4 | `amount` | REAL NOT NULL | 恒为正 |
| 5 | `pay_method` | TEXT | 支付方式原始字符串 |
| 6 | `counterparty` | TEXT | 交易对方 |
| 7 | `item` | TEXT | 商品说明 |
| 8 | `tx_type` | TEXT | 平台原始分类（如"餐饮"、"转账红包"） |
| 9 | `status` | TEXT | "交易成功" / "已退款" 等 |
| 10 | `tx_no` | TEXT | 交易单号（去重优先 key） |
| 11 | `merchant_no` | TEXT | 商户单号（去重兜底 key） |

**附加**：`remark`（用户备注）——微信/支付宝都有，直接透传。

**导出的派生字段**（代码在导入时从 `tx_time` 推导，不需人工填）：

| 派生字段 | 来源 | 说明 |
|---|---|---|
| `date` | `tx_time` 前10位 | "YYYY-MM-DD" |
| `month` | `tx_time` 前7位 | "YYYY-MM" |
| `weekday` | `tx_time` 推导 | 0=周一 |
| `hour` | `tx_time` 抽取 | 0-23 |

---

## 四、字段设计原则

**只写一次**：`source` / `tx_time` / `direction` / `amount` / `pay_method` / `counterparty` / `item` / `tx_type` / `status` / `tx_no` / `merchant_no` / `remark` 这 12 个字段在导入时写入数据库，之后不执行任何 UPDATE 操作。

**不改原始数据**：任何汇总、分类、平均值都不回写到这 12 个字段。原始数据永远是原始数据。
